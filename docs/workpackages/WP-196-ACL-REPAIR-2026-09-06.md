## Cause and correction

`20260901060000_recommendation_claim_custody.sql` transfers ownership of the eight functions
before its REVOKE/GRANT statements. Managed `postgres` had temporary SET permission but did
not actually assume the executor. The ACL statements therefore warned without applying.
Local superuser replay hid the defect. Effective worker privilege checks also missed the
missing direct worker grant because PUBLIC supplied the same effective permission.

The original operator-supplied revoke block reported success in the SQL editor, but a separate
read proved every ACL unchanged. The operator then authorized a corrected transaction. It:

1. Requires the exact eight signatures, safe role attributes and existing executor ADMIN authority.
2. Records original function metadata and all relevant membership edges.
3. Adds one temporary, non-inheriting SET grant under the operator's own grantor identity.
4. Assumes the executor, grants the worker, and revokes the four ambient grantees.
5. Resets the role, removes only that temporary grant and verifies all ACLs and snapshots.
6. Commits only if every check passes. Any failure rolls back the entire repair.
