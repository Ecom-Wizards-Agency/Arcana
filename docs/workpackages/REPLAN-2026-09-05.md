## 2. Verified findings

Each finding was produced by a reader agent, then checked by an adversarial verifier against the
code, then cross-checked by a synthesis critic. Line numbers were re-verified by hand on
`560d5e2`. Where a research report's citations were found to be fabricated, they were dropped.

### F1. Current main cannot run against the hosted database

The hosted queue schema stops at migration `20260901010000` with 41 versions. Five merged
migrations, `20260901020000` through `20260901060000`, are not applied. Since commit `ed7cb78`
(WP-194, 2026-09-02) the shared row parser `packages/db/src/queries/job-wire.ts:51-62` reads
`row.claim_token` from every claimed job; the hosted `claim_sync_jobs` returns
`setof public.sync_jobs` without that column, so the parser throws
`claim function returned an invalid claim capability` after the claim UPDATE has committed.
`apps/worker/src/store.ts:307` and `:342` also reference `claim_token is null` in SQL, which
raises `column does not exist`. The Vercel cron route
`apps/web/app/api/cron/sync/route.ts:97-101` builds `PostgresWorkerStore` and `SyncWorker` from
`@wizard-ads/worker` on main, so a web deploy from main hits the same throw on every tick, leaves
claimed rows `running`, and burns attempts to dead through `requeue_stale_sync_jobs`.

Consequence: nothing built after 2026-08-30 can be deployed until `20260901040000` is hosted.
No test in the repository exercises main against the 41-version schema; this is proven by code
reading, so WP-207 includes a disposable-database rehearsal.

### F2. Optimizer preview on main is fail-closed behind an unfinished chain

`apps/web/app/api/optimizer/runs/route.ts:32-38` and
`apps/web/app/api/optimizer/groups/run/route.ts:27-33` return 503 unless
`resolveOptimizerPreviewReadiness` in `packages/db/src/queries/recommendation-readiness.ts:44-70`
sees `OPENSPELL_RECOMMENDATION_LANE_READY=1`, fenced protocol, scoped admission and a matching
revision. That chain needs `20260901050000` and `20260901060000` hosted, a LOGIN credential for a
role the migration creates as NOLOGIN, and a root-owned authority broker whose implementation
does not exist in source (only its path in
`docs/deploy/recommendation-worker-evo-systemd-lib.sh:6,117` and its interface in
`docs/deploy/evo-recommendation-worker.md:20-31`). The deployed revision `44da7ac` has no such
gate. The runner also inserts `20260901050000` columns
(`apps/worker/src/recommendations-run.ts:1403-1408`). WP-216 adds a legacy fallback so a main
deploy does not trade a working preview for a hard 503.

### F3. Creative Performance is code-complete and already deployed; nobody flipped it on

Producer, pilot gate, lane flag parsing and lifecycle UI are ancestors of deployed web `44da7ac`.
The three SB Video migrations are in the hosted ledger. The gate is three Vercel environment
variables (`apps/worker/src/deployment-role.ts:90-100`) plus a process other than Vercel that owns
`creative.sync`, `report.request`, `report.poll`, `report.fetch` with the SB Video runtime
(`route.ts:97-101` lacks it). The producer enqueues one job per profile per profile-local day and
defers a profile while a snapshot is `report_pending`
(`packages/db/src/queries/creative-sync-producer.ts:60-100`). Because of F1 the pilot worker must
be built from a pre-`ed7cb78` revision (`397eff8` or `44da7ac`, both have zero `claim_token`
references) until WP-207 completes. Setting `OPENSPELL_EVO_REPORT_LANE_READY=1` moves all
`report.*` traffic for every profile off Vercel (`deployment-role.ts:165-175`).

### F4. Deployment drift and missing pieces

Production web is `44da7ac` (177 commits behind), MCP is `b5c210d` (317 behind), both new Evo
worker units are absent, the legacy integration worker is unstamped. Web deploys happen from the
operator machine with the Vercel CLI; no `docs/deploy/web-*.md` runbook exists. MCP has a
complete script set in `docs/deploy/mcp-evo.md` and depends on no pending migration. Report-worker
activation refuses unless `wizard-ads-worker.service` is retired
(`docs/deploy/report-worker-evo-systemd-lib.sh:8,232-245`), yet that unit is the only consumer of
`keepa.sync`, `rank.sync`, `economics.sync` and `sqp.categorize`; no replacement package exists.
The fenced report lane and recommendation lane are therefore multi-week and are not on the
two-week path.

### F5. Amazon writes: five inert layers, no consumer

Sponsored Products updates have a contract (`packages/shared/src/sp-writes.ts`), a provider
adapter (`packages/ads-api/src/sp-write-adapter.ts`), a ledger migration (`20260901020000`), an
outbox migration (`20260901030000`) and a database facade
(`packages/db/src/queries/sp-write-persistence.ts`). No worker job type, no web route and no
import in any app exists. `packages/db/src/sp-write-persistence.test.ts:8011-8100` scans
`apps/*`, deploy scripts and config for any consumer and fails on one;
`sp-write-persistence-blast.test.ts` does the same for the facade. `app.approve_sp_write_cycle`
(`20260901020000:1634`) requires `auth.uid()` and lives in schema `app`, so the web tier needs a
claims-bearing transport; the pattern already exists in `packages/db/src/testing/rls.ts:32-49`.
Every SP write RPC is granted to `service_role` only (`20260901020000:4095-4135`). Money columns
in the entity mirror are Drizzle `numeric` with `mode: 'number'`
(`packages/db/src/schema/columns.ts:16-18`) while the contract requires canonical decimal strings
(`sp-writes.ts:26-31`); the plan builder must read bids as text. The gitignored
`_local/amazon-write-authorization.json` is read by no code and uses a schema id the contract
does not define. Campaign creation has only the shared contract plus the WP-25 low-level SP
create clients (`packages/ads-api/src/client.ts:551-702`); SB v4 and SD have list endpoints only
(`packages/ads-api/src/endpoints.ts:160-197`).

### F6. The five pending migrations

All five open with a five-second `lock_timeout` and the shared advisory DDL lock, and apply in
separate transactions. `20260901020000` and `030000` are additive SP-write tables and functions.
`040000` adds `claim_token` to `sync_jobs` (ACCESS EXCLUSIVE, metadata-only), a non-concurrent
unique partial index, re-creates the claim functions with unchanged signatures, and its legacy
overload keeps returning report jobs until `activate_report_worker_fenced_claims()` is called
(`20260901040000:92-104`). `050000` adds recommendation scope columns, two unique indexes and an
FK from `recommendation_runs` to `sync_jobs`. `060000` creates two cluster-wide roles (needs
CREATEROLE), grants CREATE on `public` and `app` to the executor role, adds an FK from
`recommendations` to `recommendation_runs` that validates existing rows, and installs
statement-level triggers that take FOR SHARE on a singleton authority row for every `sync_jobs`,
`recommendation_runs`, `recommendations` and `audit_log` write. The running legacy worker must be
stopped for the window, exactly as WP-186 did.

`apps/analyst/README.md` says "Mac mini"; the `AGENTS.md` package table omits `apps/analyst`,
`packages/datadive-api`, `packages/keepa-api`, `packages/mrp-api` and five `tools/*` packages.
